# Mutation audit: events (2026-10-29)

- **Environment**: `APP_ENV=docker`, `http://localhost:3000` · **Spec**: `tests/features/events/events.ui.acceptance.spec.ts` · **Project**: `chromium-desktop` · 12 tests
- **Raw score**: 27% (14 killed / 52 mutants: 36 survived, 2 no-op)
- **Adjusted score**: 39% (14 killed / 36 that a test should catch: 14 killed + 20 gaps + 2 owned by API)
- Triage evidence: the rendered Leinster card's text and link targets, a live `PW_MUTANT=bjjevent:total-plus-one` page, and the card reader and mapper in `src/ui/pages/events/`.

The specs guard **name, type, county and pricing** well. Rotating or mangling any of
them fails 3 to 5 tests. Everything else a visitor reads on an event card can be wrong
while the suite stays green.

## Gaps

### G1 · Dates and schedule are never asserted (7 mutants)

`rotate`/`mangle` on `schedule.startDate`, `schedule.endDate`, `schedule.sessions`, and
`rotate:schedule.kind`.

- **Visitor sees**: the wrong date ("November 4" instead of "November 3"), another
  event's session times, or a weekly class shown as a fixed-date event.
- **Why nothing failed**: `getEventCardData` already reads `schedule`, but
  `ExpectedEventCard` in `events.card.mapper.ts` is
  `Pick<BjjEventCard, 'name' | 'type' | 'county' | 'pricing'>`, so `expectCardData`
  never compares it.
- **Fix**: add `schedule` to `ExpectedEventCard` and derive it in `cardFromDto`,
  mirroring the frontend's date format. The card shows `November 3, 2026`,
  `November 16, 2026 – November 18, 2026`, and session lines such as
  `November 23, 2026: 10:00 AM–4:00 PM · Day 1 - Gi Camp`. This is the highest-impact
  gap, because a wrong date sends someone to an empty mat.

### G2 · Card links are never read (10 mutants)

`rotate`/`mangle` on `eventUrl`, `organiser.website`, `location.coordinates.latitude`,
`location.coordinates.longitude` and `location.coordinates.coordinates`.

- **Visitor sees**: "More Information" opening another event's page, "Organised by"
  pointing at the wrong club, or the map pin in the wrong place.
- **Why nothing failed**: the card reader reads no `href` at all.
- **Fix**: extend `getEventCardData` with the three link targets. Find them by role and
  name: the links are named "Get more information about …", "Organised by: …" and
  "<address>. View … on map". Map them from the DTO in `cardFromDto`. The
  coordinates array survived alongside lat/long, so the reader will show which one the
  map link uses.

### G3 · Address is never read (2 mutants)

`rotate`/`mangle` on `location.address`.

- **Visitor sees**: another event's address.
- **Fix**: add an address field to the card reader and to `ExpectedEventCard` (it is the
  accessible name's prefix of the map link, so it falls out of G2's reader).

### G4 · Header total is unasserted on an unfiltered list (1 mutant)

`total-plus-one`. The header renders `pagination.totalItems` ("Found 6 events." with 5
cards shown).

- **Why nothing failed**: "visitor should see the header count match the events a
  search finds" asserts only after a search, which the app counts on the client.
- **Candidate scenario**: `visitor should see the total number of events in the header
when the list spans several pages`. The scenario uses a multi-page mocked body
  (allowed by the data policy) with, say, 45 items, then asserts "Found 45 events." with
  20 cards.

## Tests that do not prove their title

None. Every survivor is behaviour that no test title claims.

## Owned by API

- `reverse`: order by creation date is proven by the events API spec. The UI renders
  the server's order unchanged.
- `mangle:isActive`: the API excludes inactive and finished events (events API spec).

## Equivalent (never shown on the card)

- `description` (2), `organiser.name` (2), `location.venue` (2),
  `location.coordinates.placeName` (2), `calculatedCosts` (2), `status` (2), and
  `rotate:imageUrl` (1). None of these appear in the card text or link targets.

## Out of contract

- `mangle:location.coordinates.type` (`"Point ⁂"`) survived.
- `mangle:schedule.kind` and `mangle:imageUrl` each killed one test. The app or a test
  breaks on a value the contract forbids, which is a robustness signal, not adequacy.

## Questions for the product owner

1. `status` is never shown, so a **Canceled** or **Postponed** event looks the same as an
   upcoming one. Is that intended? **Answered 2026-10-31: yes, intended.**
2. The card shows the organiser's website host ("Organised by:
   leinster-grappling.example.ie"), never `organiser.name`. Is that intended? **Answered 2026-10-31: no, it should show
   `organiser.name`.** Fixed and now asserted, so `organiser.name` is no longer equivalent
   in the table below; see F5 in `specs/features/events.md`.

targets, and the session lines (`event-card-schedule-session-N`, with seed-relative dates
